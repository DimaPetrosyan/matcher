# Матчер — этап 1

Бот проверяет членство в сообществе, показывает приветствие и по кнопке
«Поехали» заводит участника. Два входа: по диплинку из группы и прямое
открытие бота.

## Что нужно до первого запуска

1. **Бот создан в BotFather**, токен вписан в `.env.development`.
2. **Бот добавлен в чат сообщества и сделан администратором.**
   Без этого `getChatMember` не даёт гарантий по другим пользователям.
3. **Сервер за пределами РФ** — Telegram доступен напрямую, прокси не нужен.
   См. оговорку про 152-ФЗ ниже.

## Запуск

```bash
bun install
docker compose up -d
bun dev
```

Схема накатывается **сама** при первом подъёме: каталог
`src/database/migrations` смонтирован в `/docker-entrypoint-initdb.d`,
и Postgres выполняет оттуда все `.sql` в алфавитном порядке.

Проверить, что база готова:

```bash
docker compose exec postgres pg_isready -U postgres
```

### Важно: автозапуск работает только на пустом томе

Postgres выполняет `initdb.d` **один раз** — при инициализации новой базы.
Если том уже существует, файлы оттуда игнорируются молча.

Отсюда два следствия:

- **Новую миграцию так не накатить.** Добавили файл — либо применяйте
  вручную, либо пересоздайте том, если данными можно пожертвовать:

  ```bash
  docker compose exec -T postgres psql -U postgres -d matcher -v ON_ERROR_STOP=1 \
    -f - < src/database/migrations/0002_что-то.sql
  ```

  ```bash
  docker compose down -v && docker compose up -d   # с нуля, данные стираются
  ```

- **Файлы должны быть исполнимым SQL целиком.** Никаких разметок вида
  `-- Down Migration`: Postgres выполнит файл до конца и снесёт только что
  созданные таблицы.

### Добавление сообщества

Ручных шагов нет. Добавляете бота в чат и делаете администратором — он сам
заводит запись и постит приветствие с кнопкой «Начать».

Если добавили обычным участником, бот честно скажет, что без прав
администратора проверить членство не сможет.

Команда `/connect` (только для администраторов чата) переотправляет это
приветствие — нужна, если сообщение потерялось в переписке.

**Слага нет.** Доступ определяется членством в чате: `/start` проверяет
человека по всем активным сообществам и пускает, если он состоит хоть
в одном. В ссылке-кнопке едет id чата — но только ради атрибуции,
на доступ он не влияет:

```
https://t.me/<BOT_USERNAME>?start=c-5488514678
```

Поэтому пересланное в соседний чат приглашение не ломается: человек оттуда
всё равно пройдёт проверку по своему сообществу.

### Переменные окружения

Все живут в `.env` в корне проекта. Bun читает его сам, библиотека не нужна.
**Файл в `.gitignore`** — там токен бота, в репозиторий он попасть не должен.

Готового шаблона в репозитории нет: список переменных — эта таблица.

| Переменная | Откуда взять | Пример |
|---|---|---|
| `BOT_TOKEN` | BotFather, при создании бота | `1234567890:AAF-abcdefghijklmnopqrstuvwxyz012345` |
| `BOT_USERNAME` | @-имя бота без собаки | `gather_us_bot` |
| `DATABASE_URL` | из `docker-compose.yml` | `postgres://postgres:postgres@localhost:5433/matcher` |
| `CONSENT_VERSION` | дата редакции политики | `2026-08-28` |
| `POLICY_URL` | ссылка на политику обработки данных | `https://…/privacy` |
| `LOG_LEVEL` | необязательна | `info` |

Без любой из первых пяти процесс упадёт на старте и перечислит все
недостающие разом.

На сервере значения задаются настоящими переменными окружения — они
перекрывают `.env`, поэтому локальный файл на прод не влияет.

### Порт 5433, а не 5432

В `docker-compose.yml` контейнер отдаёт `5433:5432`, потому что на 5432
часто уже слушает локально установленный Postgres. Если у вас он свободен
и хочется привычный порт — поменяйте и в compose, и в `DATABASE_URL`.

### Если контейнер не стартует

PostgreSQL 18 сменил точку монтирования: том подключается к
`/var/lib/postgresql`, а не к `/var/lib/postgresql/data`. При старом
пути контейнер выходит с ошибкой про «unused mount/volume».
После правки нужен `docker compose down -v`, иначе останется старый том.

## Раскладка

```
src/
  index.mts          запуск и остановка
  env.mts            переменные окружения
  database/
    index.mts        барель
    client.mts       клиент Postgres и экземпляр drizzle
    setupDb.mts      подключение к базе на старте
    migrations/      SQL, накатывается автоматически при первом подъёме
    schema.mts       таблицы drizzle
    users.mts        регистрация
    community.mts    справочник сообществ
    audit.mts        журнал действий — источник продуктовых метрик
  bot/
    index.mts        барель
    bot.mts          экземпляр, middleware, роутинг, запуск
    start.mts        обработчик /start
    consent.mts      обработчик «Поехали»
    membership.mts   getChatMember
    screens.mts      callback_data и рендер экранов
    deeplink.mts     разбор payload ссылки
  i18n/
    index.mts        барель
    translate.mts    выбор языка и подстановка
    ru.mts, en.mts   словари
```

В каждой папке `index.mts` перечисляет то, что она отдаёт наружу. Внутри
папки файлы импортируют друг друга напрямую — иначе выходят круговые импорты.

Слой `database/` не знает про Telegram: не импортирует `grammy` и ничего
из `bot/`. Проверяется тестом `boundaries.spec.mts`.

Схемой владеет SQL в `src/database/migrations/`; `src/database/schema.mts` производный —
перегенерируется через `bun run db:pull`.

## Языки

Словари в `src/i18n/` — плоские объекты со строками, без функций и условий.
Русский эталонный: его ключи задают тип `Dictionary`, поэтому пропущенный
ключ в `en.mts` — ошибка компиляции, а не пустая строка в проде.

Переменные внутри текста — `{плейсхолдеры}`. Выбор между вариантами
(`welcome` или `welcomeInCommunity`) делает рендер: это решение о показе.

Логи и сообщения об ошибках — всегда на английском: их читает разработчик.

## Проверка вручную

| Сценарий | Ожидание |
|---|---|
| По ссылке, состою в чате | Экран 2, затем `source = 'deeplink'` |
| Напрямую, состою в чате | Экран 2, затем `source = 'direct'` |
| Напрямую, **не** состою | Экран 1, в `app_user` пусто |
| `/start c-ерунда`, состою | Экран 2, `source = 'deeplink_unknown'` |
| «Поехали» дважды | `consent_at` не изменился, второго `consent_given` нет |
| Снять с бота права админа | «не могу проверить», в логах ошибка |
| `/start` в общем чате | Бот молчит |

```sql
select u.tg_id, u.source, u.status, u.consent_at, c.slug
  from app_user u
  left join user_community uc on uc.user_id = u.id
  left join community c on c.id = uc.community_id;

select type, user_id, payload, created from audit_log order by created;
```

## Оговорка про 152-ФЗ

Документ архитектуры исходил из того, что база лежит в РФ (ст. 18 ч. 5 —
локализация персональных данных). С деплоем на зарубежный VPS база уезжает
туда же, и это уже не транзит, а хранение.

Состав данных минимальный — `tg_id`, `@username`, имя из профиля, язык, —
но это персональные данные. Вопрос юридический, решать его надо до первого
живого пользователя.
